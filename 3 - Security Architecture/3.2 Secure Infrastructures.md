#### Device placement
- Every network is different
	- There are often similarities
- Firewalls: separate trusted from untrusted
- Other services may require their own security techs
	- Honeypots, jump server, load balancers, sensors
#### Security Zones
- Zone-based security technologies
	- More flexible than IP address ranges
- Each section of the network is assigned a zone
	- e.g. Trusted, untrusted
	- Internal, external
	- Inside, internet, servers, databases, screened
- This simplifies security policies
	- Can send data from trusted zone untrusted
	- untrusted to screened
	- untrusted to trusted
- Untrusted could be the internet... trusted could be anything inside the org
	- Or split the network into even more zones...
#### Attack surface
- How many ways into the network?
- Everything can be a vulnerability
	- App code
	- open ports
	- auth errors
	- human error
- Minimize the surface
	- Audit the code
	- Block ports on the firewall
	- Monitor network traffic in real-time
#### Connectivity
- Everything contributes to security, including the connection
- Secure network cabling
	- Protect the physical drops
- Application-level encryption
	- Even if attacker can capture packets, they can't know what is in them
- Network-level encryption
	- IPsec tunnels, VPN

## Intrusion Prevention
#### IPS
- Watch network traffic
- Intrusions
	- Exploits against OS, apps, etc.
- Detection vs Prevention
	- Intrusion Detection System (IDS) - alarm or alert
	- Prevention - stop it before it gets into network
#### Failure modes
- Hopefully we get 100% uptime, but what if it breaks
- **Fail-open**: when a system fails, data continues to flow
- **Fail-closed**: when a system fails, data does not flow
#### Device connections
- Active monitoring (IPS technique)
	- System is connected inline
	- Data can be *blocked in real-time* as it passes by
	- Often the default config of IPS
		- Concern for downtime or if IPS is too aggressive
- Passive monitoring
	- A copy of the network traffic is examined using a tap/port monitor
	- Data cannot be blocked in real-time
		- often called an IDS design because of this

#### Network Appliances

#### Jump server
- Access secure network zones
	- Provides an access mechanism to a protected server
- Highly-secure device
- SSH to the jump server, then jump from there to other internal servers
- A significant security concern if compromised
#### Proxy server
- Sits between the users and external network
- Receives the user requests and sends the request on their behalf (the proxy)
- Useful for caching info, access control, URL filtering, content scanning
- Applications may need to know how to use the proxy **(explicit proxy)**
- ***Transparent proxy***: proxy is invisible
#### Application proxy
- One of the simplest proxies is NAT
- Most proxies in use are application proxies
- A proxy may only know one app like HTTP, or it may know multiple like HTTP, HTTPS, FTP, etc.
#### Forward proxy
- AKA internal proxy
- Users make request to an internal proxy server that is inside your network, the request if forwardded out to the internet
#### Reverse proxy
- Inbound traffic from the internet to your internal service
- Internet makes request to your web server, it hits your proxy first, the proxy then forwards the request to you.
	- The proxy can drop the request if necessary
	- Proxy can cache responses to limit how much web traffic hits your web server
#### Open proxy
- A third-party uncontrolled proxy
	- Can be a significant security concern
	- Often used to circumvent existing security controls
- Third-party could add extra info into traffic loads, like ads or malicious codes
#### Load balancer
- Distribute the load across multiple servers
- Large-scale implementations
	- Web server farms, database farms
- Keeps load even across devices
- Fault tolerance too, if one load balancer fails, just split load across remaining servers
#### Active/active load balancing
- All servers connected to load balancer are active
- Can provide **TCP offloading** so it just keeps one TCP connection open all the time
- **SSL offload** for encryption/decryption. Encrypting is done on the load balancer so servers don't have to.
- **Caching** for faster responses to internet requests
- **Content switching** for app-centric balancing
#### Active/passive load balancing
- Some servers active, but others are on standby
- If an active server fails, the passive server takes its place
#### Sensors and collectors
- Aggregate info from network devices
	- Built-in sensors, separate devices
	- Integrated into switches, routers, servers, firewalls, etc.
- Sensors
	- IPS, firewall logs, auth logs, email logs, etc.
- **Collectors**
	- Proprietary consoles (IPS, firewall), SIEM (Security info and event manager) consoles, syslog servers
	- most SIEMs include a correlation engine for data analysis

## Port Security
- Interfaces on a switch
- Use a username and password prompt...
- Commonly used on wireless networks (can be used on wired networks)
#### EAP
- **Extensible Authentication Protocol**
	- An auth framework with many different ways to authenticate based on RFC standards
- EAP integrates with 802.1X
	- Prevents access to the network until auth succeed
#### IEEE 802.1X
- AKA Port based Network Access Control (NAC)
- Can't access to network until you auth
- EAP integrates with this
- Used in conjunction with an auth database
- **Supplicant** - the client. **Authenticator** - the device that provides access. **Authentication server** - validates the client credentials
	- EAP-request sent from authenticator to supplicant.
	- Supplicant sends a EAP-response to authenticatior, this is verified from auth server

## FIrewall Types
- Fire wall is a universal security control
	- Control the flow of network traffic
	- Corporate control of outbound/inbound data
	- Control of inappropriate content
	- Protection against evil malware
#### Network-based firewalls
- Filter traffic by port number or application
	- OSI layer 4 (TCP/UDP) vs OSI layer 7 (specific apps)
- Encrypt traffic
- Most firewalls can be layer 3 devices (routers)
	- often have NAT functionality
	- Authenticate dynamic routing configs
#### Unified Threat Management (UTM) Device
- All-in-one security applicance
- URL filter / content inspection
- Malware inspection
- Spam filter
- Wide area connectivity: CSU/DSU
- Firewall
- IDS/IPS
- Bandwidth shaper
- VPN endpoint
- Goated?
- Often all features combined will draw back performance of the UTM
#### NGFW (Next-Generation Firewall)
- OSI layer 7 Firewall
- Requires some advanced decodes
	- Every packet must be analyzed and categorized before a security decision is determined
- Control traffic flows based on the application
	- Maybe let in Microsoft SQL Server, maybe you can view twitter but not post, maybe let YouTube in only through port 24852
- Intrusion Prevention Systems
	- I.D. the app
	- Apply app specific vulnerability signatures to the traffic
- URL filters, control website traffic by category (nice!)
#### Web application firewall (WAF)
- Not like a normal firewall
	- Applies rules to HTTP/S conversations
- Allow or deny based on expected input
	- Unexpected input is a common method of explotiing an app
- e.g. SQL injection
- A major focus of Payment Card Industry Data Security Standard (PCI DSS)
- Often used in conjunction with NGFW
