#### Data types
- **Regulated**, e.g. managed by a third party
	- Government laws/statutes, like credit card data
- **Trade secret**: An org's secret formulas
- **Intellectual property**: May be publicly visible
	- Copyright and trademark laws
- **Legal information**
	- Court records & docs, judge/attorney info
	- PII and other details may be masked
	- Usually stored in many diff systems
- **Financial information**
	- Customer/company finanicals
	- Payment records, bank records
#### Data types - cont.
- Human-readable
- Non-human readable e.g. barcodes
- Hybrid
	- CSV, XML, JSON, etc.
#### Classifying sensitive data
- Health records are much more sensitive than license tag numbers
	- Add extra permissions, a different process to view the data, or restrict network access to the data source
- **Proprietary**: Data that is the property of an organization
	- Can include trade secrets
	- Data is often unique to the org
- **PII**: Data that can be used to identify an individual
- **PHI** - Protected Health Information
	- Health info associated with an indiv
	- Health status, records, payments, more
#### Data Classifications
- Sensitive
	- Intellectual property, PII, PHI
- Confidential
	- Very sensitive, must be approved to view
- Public
	- No restrictions
- Private / Classified
	- May require NDA
- Critical
	- Should always be accessible

## States of Data
#### Data at rest
- Data is on a storage device
- Encrypt the data
	- Whole disk
	- Database
	- File/folder level
- Apply permissions to access this data
#### Data in transit
- Data transmitted over the network. aka. data in-motion
- Not much protection while it travels
- Network-based protection
	- Firewall / IPS
- Provide transport encryption e.g. TLS or IPsec
#### Data in use
- Data is actively processing in memory
	- RAM, CPU, cache, registers
- Almost always in decrypted form
- Attackers can pick the decrypted info out of RAM
#### Data Sovereignty
- Data that resides in a country is subject to the laws of that country
	- applies for legal processings and court orders
- Laws may prohibit where data is stored
	- GDPR (General Data Protection Regulation) for EU
		- Data collected on EU citizens must be stored in EU
#### Geolocation
- Location details; involves a number of diff technologies
- 802.11 info, GPS info, mobile provider info
- Can be used to manage data access. Like preventing access from other countries
- Limit administrative tasks unless secure area is used

## Protecting Data
#### Geographic restrictions
- Network locations
	- Identify based on IP subnet
	- Difficult with mobile networks
- Geolocation - determine a users locations 
	- GPS - best for mobile
	- 802.11 / IP
- **Geofencing**
	- Automatically auto/restrict access when the user is in a particular location
#### Protecting Data
- Data is everywhere, how can we secure it?
#### Encryption
- Encode info into unreadable data (plaintext -> ciphertext)
- This is a two-way street, decryption is possible w/ right key
- **Confusion**: Encrypted data is drastically different than plaintext
#### Hashing
- Represent data as a short string of text (a fingerprint/digest)
- One-way trip
- Verify a download document is same as original
	- Integrity verification 
- Can be a digital signature
	- Provides authentication, non-repudation, and integrity
- Lowkey goated
- Avoid collisions hopefully
#### Obfuscation
- Make something normal understandable very difficult to understand
- Take perfectly readable code and turn it into nonsense to protect codebase
- Can be used in malicious code too
#### Data Masking
- hides some of original data
- Protects PII and other sensitive data
- May only be hidden from view but in storage
- Many techniques eg substituting, shuffling, encrypted, masking out, etc
#### Tokenization
- Replace senstiive data with a non-senstivie placeholder
- Common w/ credit card processing
	- attacker capturing the card numbers can't use them later
- Not encrypted or hashing
#### Segmentation
- Many orgs use a single data source... obviously bad
- Separate the data into smaller pieces, put it in diff locations
- Sensitive data should have stronger security
