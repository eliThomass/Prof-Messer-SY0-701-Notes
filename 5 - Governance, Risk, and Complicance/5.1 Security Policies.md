#### Security policy guidelines
- What rules are we following to provide CIA?
- We need rules everyone follows to maintain this kind of security
- High level strategies
	- Data storage requirements, security event procedures
- Detailed security goals
- Security policies answer the "what" and "why"
	- Technical security controls answer the "how"
#### Information security policies
- The big list of all security-related policies
- Compliance requirements
- Detailed security procedures
	- What happens when..? (situation)
- A list of roles and responsibilities
- This is just words and letters
	- An org has to actually enforce this
#### Acceptable use policies (AUP)
- What is acceptable use of company assets?
	- Detailed documentation
- Covers many topics
	- Internet use, telephones, computers, mobile devices, etc.
- Used by an organization to limit legal liability
#### Business continuity
- Not everything goes according to plan
- There needs to be an alternative to computer systems if they go down
	- Manual transactions
	- Paper receipts
	- Phone calls for transaction apprvoals
- These must be documented and tested before a problem occurs
#### Disaster recovery plan
- IT needs to be ready if a disaster happens
- Business continuity plan which applies to everything affected by the disaster
- Keep the organization up and running
- **A comprehensive plan*
	- Recovery location
	- Data recovery method
	- Application restoration
	- IT team and employee availability
#### Security incidents
- User clicks an email attachment and executes malware
	- Malware then communicates with external services
- DDoS
	- Botnet attack
- Confidential info is stolen
	- Can turn into a ransom
#### Incident response roles
- Many different kinds of roles for responding to security incidents
- *Incident response team*
	- Specialized group, trained and tested
- *It security management
- *Compliance officers*
	- Knowledge of compliance rules
- *Technical staff*
- *User community*
	- They see everything
#### SDLC
- Many ways to get from idea to app
	- Many moving parts to keep track of
	- Customer requirements
	- Keeping process on schedule
	- Stay on budget
- Many SDLC frameworks and options to do this
- Agile (constant loop) and Waterfall (linear)
#### Change management
- How to make a change?
- A common risk
- Often overlooked or ignored
- Have clear polcieis
	- For frequency, duration of change, installation process, fallback procedures

## Security Standards
- A formal definition for using security technology and processes
	- Complete documentation reduces security risk
- These may be written in-house
- Many standards are already available
	- ISO
	- NIST
#### Password
- What makes a good password?
	- Every org has their own requirements
	- Create a formal password complexity policy
- Define acceptable authentication methods
	- No local accounts, only LDAP to the AD database, etc.
- Create policies for secure password resets
- Other password policies, like change frequency, password storage, password managers, etc.
#### Access control
- How does an organization control access to data?
- Define which access control types can be used
	- E.g. no discretionary, mandatory only, etc.
- Determine how a user gets access
	- Requires privilege documentation
- Document how access may be removed
#### Physical security
- Rules and policies regarding physical security controls
	- Doors, building access, property security
- Granting physical access through an ID badge
	- Might be different for employees vs contractors vs guests
- Define specific physical security systems
	- Electronic door locks, motino detection, monitoring systems
- Additional security concerns
	- Mandatory visitor escorts, off-boarding, etc.
#### Encryption
- Define specific standards for encrypting and securing data
	- Implementation standards and what algorithms to sue
- Password storage: methods and techniques
- Data encryption minimums
	- Algorithms for data in use, in transit, and at rest
		- Probably different requirements depending on state of data

## Security Procedures
#### Change management
- A formal process for managing change
	- Avoid downtime, confusion, and mistakes
- Nothing changes without the process
	- Determine the scope, analyze the risk, create a plan, get approval from a end-user
	- Present the proposal to the change control board
	- Have a backout plan if the change doesn't work
	- Document the changes after application
#### Onboarding
- Bring a new person into the organization
- IT agreements needs to be signed, like AUPs
- Create accounts
	- Associate the user with the proper groups and departments
- Provide required IT hardware
#### Offboarding
- This process should be pre-planned
- What happens to the hardware? More importantly, the data?
- Account info is usually deactivated, but not always deleted
#### Playbooks
- Conditional steps to a follow; a broad process
	- e.g. Investigate a data breach, recover from ransomware
- Step-by-step set of processes and procedures
	- Many playbooks are made
- Often integrated with a Security Orchestration, Automation, and Response (SOAR) platform.
	- Make security teams more effective with automation
#### Monitoring and revision
- IT security is constantly changing
- Update to security posture
	- More playbooks
- Change to an individual procedure
	- Update the playbooks
- New security concerns
#### Governance structures
- Boards
	- A panel of specialists
	- Set the tasks for the committees
- Committees
	- Subject-matter experts
	- Considers input from a board
	- Determine next steps for a topic at hand
	- Present results to the board for feedback
- Government entities
	- A diff kind of machine
	- Legal concerns, administrative requirements, political issues
	- Often open to the public
- Centralized/decentralized
	- Centralized governance is located in one location with a group of decision makers
	- Decentralized spreads the decision-making process around to other individuals or locations

## Security Considerations
#### Regulatory
- Regulations are often mandated
	- Logging, data storage, data protection / retention
- **Sarbanes-Oxely Act (SOX)**
	- The Public Company Account Reform and Investor Protection Act of 2002
	- Focuses on the finances of an information
	- HIPAA (Health Insurance Portability and Accountability Act)
#### Legal
- The security team is often tasked with legal responsibilites
	- Reporting illegal acts
	- Holding data for legal proceedings
- Security breach notifications
	- Legally mandated to disclose the breach to user's in a time frame
- Cloud computing can make this challenging
	- Data moves between jurisdictions without human intervention
	- There may be legal guidelines as to where info might be stored
#### Industry
- The industry may require specific security considerations, every market is different, for example:
- Electrical power and public utilities
	- Isolated and protected system controls (air gap electricity in homes)
- Medical
	- Highly secure data storage and access logs
	- Data encryption and protection
#### Geographical Security
- Local/regional
	- City and state govt. records
- National
	- Federal govt. and national defense
	- Multi-state organizations may communicate together for this
	- State secrets must remain secret with new technology
	- Legal concerns will vary widely

## Data Roles and Responsibilities
#### Data responsibilties
- High-level data relationships
- **Data owner**
	- Accountable for specific data, often a senior officer
	- Broadly responsible for data they control
		- VP of sales owns the consumer relationship data
- **Data controller**
	- Manages the purposes and means by which the personal data is processed
- **Data processor**
	- Processes data on behalf of the data controller
	- Often a third-party
- e.g. payroll controller (payload department) will define payroll amounts and timeframes. Then the payroll company (data processor) will processes the payroll and store the employee info
- **Data custodian**
	- Responsible for data accuracy, privacy, and security
	- is the organiztaion in compliance with laws associated with the data?
	- they work directly with the data
	- implements security controls, manages access rights, etc.
