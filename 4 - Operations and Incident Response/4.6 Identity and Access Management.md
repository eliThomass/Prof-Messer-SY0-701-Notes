#### Identity and Access Management (IAM)
- Applications are available everywhere
	- Desktop, browser, mobile device, etc.
- Data can be located anywhere
- Many different application users
- Give the right permissions to the right people at the right time
- Identify lifecycle management
- Access control
	- An entity only gets access to what it needs
- Authentication and Authorization
	- Entities must prove they are who they claim
- Identity governance
	- Track and entity's resource access
#### Provisioning / De-provisioning user accounts
- The user account creation and removal process
- Occurs for certain events
	- Hiring, transfers, promotions, job separation
- Account details
	- Name, attributes, group permissions, other permissions
- A core part of the IAM process
	- An initial checkpoint to limit access
#### Permission Assignments
- Each entity gets just enough perms to do its job
	- Group assignments are common
- Storage and files can be private to that user, even if another person is using that computer
- No priv access to the OS, specifically on user accounts
#### Identity Proofing
- An IAM process should confirm who I am
- **Resolution:** who the system thinks you are
- **Validation:** gathering info from the user lke password, security questions
- **Verification / Attestation**: Extra details to prove identity, like a passport or in-person meeting.
#### Single sign-on (SSO)
- Provide credentials one time
	- No additional auth required
	- Without it, you would need a username/password every time
- Usually limited by time, such as a 24 hour limit
- The underlying auth process must support SSO for it to work.
#### LDAP (Lightweight Directory Access Protocol)
- Protocol for reading and writing directories over an IP network
#### X.500
- X.500 specification
	- X.500 distinguished names
	- Most specific attribute is listed first
- **X.500 Directory Information Tree**
	- Hierarchical structure builds a tree
	- Container objects (country, org, org units)
	- Leaf objects
#### SAML (Security Assertion Markup Language)
- Open standard for authentication and authorization
	- You can authenticate through a third-party to gain access
- Not originally designed for mobile apps

#### OAuth
- Authorization framework
	- Determines what resources a user will be able to access
- Created by Twitter, Google, and others
- Not an authentication protocol
	- Used OpenID with OAuth
- OAuth is where an app like Claude asks for access to see, edit, create Google drive files. You press allow and it works.
#### Federation
- Provide network access to others
- Provides SSO and more
- Allows access without a local authentication database
- Third-parties can establish a federated network
	- Login with your google credentials
- The third parties must establish a trust relationship
- "Log in with X, Log in with Google, etc."
#### Interoperability
- Many different ways to communicate with an authentication server
- Often determined by what is at hand
	- VPN concentrator can talk to a LDAP server
	- If the organization has an LDAP server, perfect!
- A new app uses OAuth
	- Need to allow authentication API access for OAuth then for the org
- The interoperability is dependent on the enviornment

## Access Control
- Authorization
	- The process of ensuring only authorized rights are exercised
- Users receive these rights based on Access Control models
#### Least privilege
- Rights and perms should be set to bare minimum necessary for users
- All user accounts must be limited, don't let them run admin privileges
#### Mandatory Access Control (MAC)
- The OS limits the operation on an object based on security clearance levels
- Every object gets a label, e.g. secret or top secret
- Labeling of objects uses predefined rules
	- Who has access, who can write.
	- Users cannot change this
#### Discretionary Access Control (DAC)
- Used in most OS'
- You create a spreadsheet
	- You are the owner, so you control the access
	- You can modify access at any time
- Very flexible access control
	- And very weak security...
#### Role-based access control (RBAC)
- You have a role in your organization
	- Manager, team lead, director
- Admins provide access based on the role of the user
	- Rights are gained implicitly based on the group you are placed into
- In Windows, use Groups to provide RBAC
#### Rule-based access control
- Generic term for following rules
- Access is determined through system-enforced rules
	- System admins configured these
- The rule is associated with a specific object
	- System checks the ACLs for that object
- Rule examples
	- Lab network access is only available between 9AM and 5PM
	- Only Chrome browsers may complete a web form
#### Attribute-based access control (ABAC)
- Users can have complex relationships to apps and data
- ABAC can consider many parameters
	- A next generation authorization model
	- Aware of context
- Combine and evaluate multiple parameters
	- Resource info, IP address, time of day, desired action, relationship to data, etc.
#### Time-of-day restrictions
- Almost all security devices include a time-of-day option
- Restrict access during certain times or days of the week
- Can be difficult to implement if you are a worldwide organization

## Multifactor Authentication
- Prove who you are
	- Use different methods
- Factors
	- Something you know, something you have, something you are, somewhere you are
#### Something you know
- Password
- PIN
- Pattern (android users...)
#### Something you have
- Smart card, may require a PIN
- USB security key
	- Certificate is on the USB device
- Hardware/software tokens
- Your phone (SMS)
#### Something you are
- Biometric authentication
	- Fingerprint, iris scan, voice print
- Usually stores a mathematical representation of your biometric
- Difficult to change, unlike a password
- Used with other factors other as it's not foolproof
#### Somewhere you are
- Provide a factor based on your location
	- The transaction only completes if you are in a particular geography
- IP address
- Mobile device location services

## Password Security
#### Password complexity and length
- Make it strong, to resist brute force
- Increase password entropy (unpredictability)
- Stronger passwords are commonly at least 8 characters
#### Password age and expiration
- Password age is how long since it has been modified
- Password expiration
	- Pass only works for a certain amount of time
	- After date, the password doesn't work
	- System remembers password history
- Time determined by system admin
#### Password managers
- Important to use different passwords for each account
	- Remembering them all is hard though
- So, store all your passwords in a single database
	- Encrypted, protected
	- Can include multifactor tokens to login
- Built-in to many OS' and some browsers
- Enterprise password managers
#### Passwordless authentication
- Many breaches are due to poor password control
	- Weak passwords, insecure implementation
- Authenticate without a password
	- This solves many password management issues
- Facial recognition, security key, etc.
	- May not be the primary authentication method, though, maybe use it in conjunction.
#### Just-in-time permission
- In many orgs, the IT team is assigned admin account rights
	- Great for an attacker to abuse
- Grant admin access for a limited time
	- No permanent admin rights
	- Follows principle of least priviledge
- A breached user account never has elevated rights, which narrows scope of breach
- Request access from a central clearinghouse (password vault)
	- The vault sets different controls for each user
	- It will make a temporary account with elevated privileges
	- They are then deleted after the session is complete
