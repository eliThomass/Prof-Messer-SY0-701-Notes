#### Network-based firewalls
- Filter traffic by port number or application
	- Traditional vs NGFW
- Encrypt traffic
	- VPN between sites
- Most firewalls can be layer 3 devices
	- Often sits on the ingress/egress of the network
	- Provides NAT and dynamic routing
#### Next-generation Firewalls (NGFW)
- The OSI application layer
	- Layer 7 (app) firewall
- Can be called diff names
	- App layer gateway
	- Deep packet inspection device
	- Stateful multilayer inspection device
- Requires some advanced decodes
	- Every packet must be analyzed, categorized, and a decision determined
#### Ports and protocols
- Make forwarding decisions based on protocol and port number
	- Add to NGFW for additional security policy options
	- Traditional port-based firewalls do this
- Based on both protocol and port e.g. tcp/443 (https), or udp/53 (DNS)
#### Firewall rules
- A logical path
	- Usually top-to-bottom
- Usually more specific rules are at the top, then more generic rules are lower down in the rulelist
- Implicit deny
	- Include a deny at the bottom if no rules match traffic
- **Access control list (ACL)**
	- Allow or disallow traffic
	- Grouping of categories, source ip, dest ip, port number, policy, more

#### Screened subnet
- An additional layer of security between you and the Internet
- Commonly holds services/devices that need to be accessed by the Internet
	- Prevents any from the Internet from accessing the internal network
	- Traffic is redirected to this screened subnet
#### IPS rules
- Intrusion Prevention System usually integrated into a NGFW
- Different ways to find malicious traffic such as looking at it as it passes by
- Signature-based
	- Look for a perfect match of a software signature
- Anomaly-based
	- Build a baseline of what's normal.
	- Unusual traffic patterns are flagged
- You determine what happens when unwanted traffic appears (block, allow, send an alert, etc.)
- Usually IPS has thousands of signatures inside
- Rules can be customized by group

## Web Filtering
#### Content filtering
- Control traffic based on the data within the content
- Corporate control of outbound/inbound data
- Control of inappropriate content
- Protection against evil websites with malware
#### URL scanning
- Allow or restrict based on Uniform Resource Locator
	- AKA a Uniform Resource Identifier (URI)
	- Allow list/block list
- URLs managed by category
	- e.g. auction, hacking, malware, travel, recreation, etc.
- Can have limited control, as URLs aren't the only way to surf
- Often integrated into an NGFW
#### Agent based content filters
- Install client software on the user's device
	- Usually managed from a central console
- Decision process occurs on users device directly
- Users can be located anywhere, always-on, always filtering
- Updates must be distributed to all agents
	- Use cloud based updates, have the update status in the central console
#### Proxies
- Sits between the users and the external network
- Allows you to control the flow of traffic thru the proxy
- Receives the user requests and sends the request on their behalf
- Also useful for caching information and access control
- Apps may need to know how to use the proxy **(explicit proxy)**
- Some proxies are invisible **(transparent proxy)**

#### Block rules
- Based on specific URL
- \*.professormesser.com: Allow
- Category of site content
	- Usually divided into over 50 diff topics
- Different dispositions
	- Educational: Allow
	- Home and Garden: Allow and Alert
	- Gambling: Block
#### Reputation
- Filter URLs based on perceived risk
	- Good reputation is allowed
	- Bad rep is blocked...
	- Risk: Trustworthy, Low/medium/high risk, suspicious
- Automated reputation
	- Sites are scanned and assigned a reputation
- Manual reputation
	- Managers can set a rep themself
- Add dispositions to the content filter!
#### DNS Filtering
- Before connecting to a website, get the IP addr with a DNS lookup
- DNS is updated with real-time threat intelligence
- Harmful sites are not resolved by DNS server
- This works for any DNS lookup, not just web filtering

## Operating System Security
#### Active Directory
- A database of everything on the network
	- Computers, user accounts, file shares, printers, groups, more
	- Windows-based
- Manage all of our authentication from this resource
	- Users login using their AD credentials
- Centralized access control list
	- Determine which users can access resources
- Commonly used by the help desk for passwords, account add/remove
#### Group Policy
- Manage the computers or users with Group Policies
	- Local and domain polciies
- A central console, the **Group Policy Management Editor**
	- Login scripts
	- network configs
	- security parameters
- Comprehensive control
	- Hundreds of config options
#### Security-Enhanced Linux (SELinux)
- Security patches for the Linux kernel
	- Adds mandatory access control (MAC) to Linux
	- Linux traditionally uses Discretionary Access Control (DAC)
- Limits application access
	- Uses least privilege
	- A potential breach will have limited scope

## Secure Protocols
#### Unencrypted Network Data
- Network traffic is important data
- Some protocols aren't encrypted like Telnet, FTP, SMTP, IMAP
- Verify with a packet capture 
#### Protocol Selection
- Use a secure application protocol
- A secure protocol may not be available
	- Can be a deal-breaker
#### Port selection
- Secure and insecure application connections may be available
	- Secure/insecure often run on different ports
- HTTP and HTTPS
	- Port 80 vs 443
- The port number does not guarantee security
#### Transport method
- Don't rely on the application, encrypt everything
- 802.11 Wireless
	- Open access point: no transport-level encryption
	- WPA3: All user data is encrypted
- Virtual Private Network (VPN)
	- Create an encrypted tunnel

## Email Security
#### Challenges
- The protocols used to transfer emails include relatively few security checks... easy to spoof emails
- Spoofing happens all the time
	- How can you tell?
- A reputable sender will configure email validation... see below notes
#### Mail gateway
- The gatekeeper of all mail for an organization
	- Evaluates the source of inbound email messages
	- Blocks it at the gateway before it reaches the user
	- On-site or cloud-based
#### Sender Policy Framework (SPF)
- SPF protocol
	- Sender configures a list of all servers authorized to send emails for a domain
- List of authorized mail servers are added to a DNS TXT record
	-  Receiving mail servers peform a check to see if incoming mail comes from an authorized host
- Who can send mail on your behalf?
#### Domain Keys Identified Mail (DKIM)
- A mail server digitally signs all outgoing mail
	- The public key is in the DKIM TXT record
- The signature is validated by the receiving mail servers
	- Not usually seen by the end user
#### DMARC
- **Domain-based Message Authentication, Reporting, and Conformance (DMARC)**
- The domain owner decides what receiving email servers should do with emails not validating using SPF and DKIM
	- That policy is written into a DNS TXT record
	- e.g. Accept all, send to spam, or reject all
- Compliance reports are sent to the email administrator
	- Domain owner can make reports on validation statistics or is someone is spoofing their domain

## Monitoring Data
#### FIM (File Integrity Monitoring)
- Some files change all the time
	- Some files should NEVER change
- Monitor important operating system and app files
	- Identify when changes occur
- Windows - **SFC (System File Checker)**
- Linux - **Tripwire**
- Many host-based IPS options
	- A little different than network based IPS systems, as it can physically monitor all files
#### Data Loss Prevention (DLP)
- If someone is transmitting sensitive info, we can block that traffic in real time
- Stop the data before the attackers get it
- Often requires multiple solutions, maybe a software DLP and network DLP
- On your computer DLP
	- **Data in use or Endpoint DLP**
	- Usually watches your RAM
- On your network DLP
	- **Data in motion**
- On your server
	- **Data at rest**
#### USB blocking
- DLP on a workstation
	- Allow/deny certain tasks
- November 2008 - US DoD was infiltrated with USB storage
	- This resulted in a local DLP agent that would block all USB connections to stop future attacks
#### Cloud-based DLP
- Located between users and the Internet
	- Watch every byte of network traffic
- Block custom defined data strings
- Manage access to URLs to prevent file transfers to cloiud
- Block viruses / malware
#### DLP and email
- Email continues to be the most critical risk vector
- Check every email inbound and outbound
- Inbound
	- Block keywords, ID imposters, quarantine email messages
- Outbound
	- Fake wire transfers, W-2 transmissions, employee information

## Endpoint Security
#### The endpoint
- The user's access
- Stop the attackers, monitor inbound and outbound traffic
- Many different platforms to monitor
	- Mobile, desktop, etc.
- Protection is multi-faceted, we need defense in depth
#### Edge vs. Access control
- Control at the edge
	- Your internet link
	- Managed primarily through firewall rules
	- Firewall rules rarely change
- **Access control list (ACL)**
	- Control from wherever you are
	- Access can be based on many rules
		- By user, group, location, app, etc.
	- Access can be easily revoked or changed
#### Posture Assessment
- You can't trust everyone's computer
	- We must constantly perform checks, called **Posture Assessments**
- Looking for any part of device not up to latest standards of security
	- App versions, anti-virus, etc.
- Best time to do this is when device first connects to the network
- **Persistent agents**
	- Permanently installed onto a system
	- Monitors all apps for the posture assessment
- **Dissolvable Agents**
	- No install is required
	- Runs during the posture assessment
	- Terminates itself and removes itself when no longer needed
- **Agentless NAC**
	- Integrated with Active Directory
	- Checks are made during login/logoff
	- Can't be scheduled
#### Failing your assessment
- Quarantine system, put it on it's own VLAN
- Once resolved, try again
#### Endpoint detection and response (EDR)
- A different method of threat protection
	- Scale to meet increasing number of threats
- Detect a threat
	- Signatures aren't the only tool
	- Behavioral analysis, machine learning, process monitoring
	- Lightweight agent on the endpoint
- Investigate the threat
	- **Root cause analysis**
- Respond to the threat
	- Isolate system, quarantine the threat, rollback to a previous config
	- API driven, no user intervention required.
#### Extended Detection and Response (XDR)
- An evolution of EDR
	- Improved missed detections, false positives, and long investigation times
	- Attacks involve more than just the endpoint
- Add network-based detection
- Correlate endpoint, network, and cloud data
	- Instead of just one agent with EDR, use multiple with XDR
#### User behavior Analytics
- XDR commonly includes user behavior analysis
- Watch users, hosts, net traffic, data repos, etc.
	- Create baseline for normal activity
	- Requires data analysis over an extended period
- Watch for anything unusual
	- Use a ruleset, pattern matching, stat analysis
