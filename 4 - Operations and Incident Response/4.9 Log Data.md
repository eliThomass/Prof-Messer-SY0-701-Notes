#### Security log files
- Detailed security-related information
	- Blocked and allowed traffic flows
	- Exploit attempts
	- Blocked URL categories
- Critical security information
	- Documentation of every traffic flow
#### Firewall logs
- Traffic flows through the firewall
	- source/dest IP
	- port numbers
	- disposition on traffic flows
- NGFW
	- Logs the application used, URL filtering categories, anomalies and suspicious data
#### Application logs
- Specific to the applicatoin
- Windows
	- Event viewer / application log
- Linux / MacOS
	- /var/log
- Parse the log details on the SIEM (sys info and event manager)
#### Endpoint logs
- Attackers often gain access to endpoints
- There's lots of data on the endpoint
	- Logon events, policy changes, system events, processes, account management, etc.
- Everything rolls up to the SIEM
- Use with correlation of security events
	- Combine IPS events with endpoint status 
#### OS-specific security logs
- OS security events
	- Monitoring apps
	- Brute force attempts, file changes
	- Authentication details
		- Find problems before they happen
		- Brute force attacks, disabled services that shouldn't be
- May require filtering
	- Don't forward everything
#### IPS/IDS logs
- Usually integrated into an NGFW
- Logs contain info about predefined vulnerabilities
	- Known OS vulnerabilities, generic security events
- Has common data points
	- Timestamp, type of attack, source/dest ip, etc
#### Network logs
- Switches, routers, APs, VPN concentrators
- Network changes
	- Routing updates
	- Authentication issues
	- Network security issues
#### Metadata
- Data that describes other data sources
- Email
	- Header details, sending server, destination address
- Mobile
	- Type of phone, GPS location
- Web
	- OS, browser type, IP
- Files
	- Names, address, phone number, title
#### Vulnerabliity scans
- Check for lack of security controls
	- No firewall, anti-virus, anti-spyware
- Check for misconfigs
	- Open shares
	- Guest access instead of disabled
- Real vulnerabilities
	- Especially newer ones
#### Automated reports
- Most SIEMs include a report generator
- May be easy or complex to create
	- If SIEM has it, great, otherwise use a 3rd party report generator
- Requires human intervention
	- Someone still needs to read these reports
- Can be complex to create and process and store
#### Dashboards
- Real-time status information
	- Get summaries on a single screen
- Add/remove information
	- Most SIEMs and reporting systems allow for customization
- Shows the most important data
	- Not designed for long-term analysis
#### Packet captures
- Solve complex application issues
	- Get into the nitty gritty details
- Gather packets on the network using a utility like Wireshark
	- Sometimes built into the device
- View detailed traffic info
	- ID unknown traffic
	- Verify packet filtering and security controls working
