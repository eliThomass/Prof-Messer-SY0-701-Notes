	- May require constant updates

## Hardening Targets
- No system is secure with the default config
- Hardening guides are specific to the software or platform and given by the manufacturer or the internet
#### Mobile Devices
- Always connected mobile tech must be hardened
- Manufacturers release patches for bug fixes but also include security updates
- Segmentation can protect data
	- Separate company and user data
- Control with an MDM (Mobile Device Manager)
#### Workstations
- Constant monitoring/updates
	- OS, apps, firmware, etc.
- Automate the monthly patches
- Connect to a policy management system
- Remove unnecessary software to limit threats
#### Network Infra Devices
- Switches, routers, etc. need hardening
- Usually use an embedded OS so we have limited OS access
- Configure auth, don't use default creds
- Check with the manufacturer for patches if needed
#### Cloud Infra
- Secure the cloud management workstation!
- Least privilege for all services, network settings, app rights
- Configure Endpoint Detection and Response (EDR)
- Always have backups
	- Cloud to Cloud (C2C)
#### Servers
- Updates
	- OS updates / service packs
- User accounts 
	- Min pass length and complexity
	- Account limitations
- Limit network access
#### SCADA / ICS
- **Supervisory Control and Data Acquisition System**
- Large scale, multi-site Industrial Control Systems (ICS)
- PC manages equipment
	- Power gen, refining, manufacturing equipment
- Distributed control systems with real time info
- Requires extensive segmentation, no outside access at all
#### Embedded Systems
- Can be difficult to upgrade
- Watches/TVs are relatively easy
- Other devices may not be easily modified
- Correct vulnerabilities in these with security patches
- Segment and firewall to prevent access from unauthorized users
#### RTOS (Real Time OS)
- An OS with a deterministic processing schedule
	- No time to wait for other processes
- Isolate the system from rest of network
- Run w/ minimum services to remove exploit potential
- Use secure communication
	- Protect w/ host-based firewall
#### IoT Devices
- Heating / cooling, lighting, home automation, wearable tech, etc.
- Weak default common, change those passwords
- Deploy updates quickly
- Segmentation by putting them on their own VLAN

## Securing Wireless and Mobile
#### Site Surveys
- Determine existing wireless landscape
	- Sample the existing wireless spectrum. Use a **heat map**
- I.D. all the APs
- Work around existing frequencies
	- Layout and plan for interference
- Plan for ongoing site surveys at regular intervals
#### Wireless Survey Tools
- Signal coverage overview
- NetSpot -> like Wireshark but specifically for wireless networks and bandwidths
- See potential interference
- built-in tools on your OS, or use 3rd party tools (NetSpot)
- Spectrum analyzer, this will show you all signals from a particular freq
#### Mobile Device Management (MDM)
- Manage company-owned and user-owned mobile devices
	- BYOD - Bring your own device
- Centralized management of the mobile devices with specialized functionality
- Set policies on apps, data, camera, etc. to control the remote device
	- Also can set partitions on your device for business use
- Manage access control
	- Force screen locks and PINs for these devices
#### BYOD - Bring Your Own Device
- Employee owns the device, but it must meet the company's requirements
- Difficult to secure as it's both a home device and work device
	- Protect two sides of the data
	- Protect if the phone is traded in
#### COPE - Corporate Owned, Personally Enabled
- Company buys the device
- Used as both a corporate device and a personal device for employees
- Could be exclusively for corporate use, not as common
- Org keeps full control of the device
	- Similar to company-owned laptops / desktops
- Info is protected using corporate policies. Info can be deleted at any time
- CYOD - Choose Your Own Device
	- Employee can choose their corporate owned device to use
#### Cellular networks
- Mobile devices are cell phones
- Separate land into "cells"
- Security concerns, we need to maintain updates patches for devices connected to these cell phone towers, since we can't manage them
#### Wi-Fi
- Local network access
- Encrypt all data, but this isn't always possible, so use a VPN
- On-path attack (MITM)
	- Modify and/or monitor data
- Denial of service
	- Frequency interference
#### Bluetooth
- PAN (Personal Area Network)
- Connect our mobile devices
- Do not connect to unknown Bluetooth devices

## Wireless Security Settings
#### Securing a wireless network
- Auth the user before granting access to wireless network
- Username, pass, MFA
- Ensure all communication is confidential
- Verify the integrity of comms, like using a **message integrity check** (MIC)
#### WPA2 PSK Problem
- WPA2 has a PSK brute-force problem
	- 4-way handshake that occurs during the initial connection
	- Some methods can derive the PSK hash w/o handshake
		- Capturing the hash
- With the hash, attackers can brute force the pre-shared key (PSK)
- This is becoming even easier with device speed
- Once you have the PSK, you have everyone's wireless key, there is no secrecy
#### WPA3 and GCMP
- GCMP block cipher mode
	- Galois/Counter Mode Protocol
	- Better encryption
- GCPM security services
	- Data confidentiality with AES
	- Has a MIC using Galois Message Auth Code (GMAC)
#### SAE
- WPA3 changes the PSK auth process
	- Includes mutual auth
	- Creates a shared session key w/o sending that key across the network
	- No more four way handshakes so no more attacks
- **Simultaneous Authentication of Equals (SAE)**: better way to get a PSK
	- A derivation of Diffie-Hellman 
	- IEEE Standard
	- Everyone uses a diff session key, even with the same PSK
#### Wireless Authentication Methods
- Gain access to a wireless network
- Credentials
	- Shared password / pre-shared key (PSK)
	- Centralized authentication (802.1X)
- Configuration
	- Part of the wireless network connection
	- Prompted during the connection process (like eduroam)
#### Wireless security modes
- Configure the auth on your wireless router
- Open system
	- No auth is required
- **WPA3-Personal / WPA3-PSK**
	- WPA3 with a PSK, everyone uses same 256-bit key
- **WPA3-Enterprise / WPA3-802.1X**
	- Authenticates users individually with an auth server
#### AAA Framework
- Identification: This is who you claim to be
- Authentication: Prove you are who you claim to be
- Authorization: Based on your ID + Auth, what access do you have?
- Accounting: Logs the data you used & logout/in time
#### RADIUS (Remote Authentication Dial-in User Service)
- A common AAA protocol
- Centralize authentication for users
	- Routers, switches, firewalls
	- Server auth
	- Remote VPN access
	- 802.1X network access
- RADIUS is available on almost any server OS
#### IEEE 802.1X
- Port-based Network Access Control (NAC)
- You don't get access to net until you auth
- Not just for wireless, but wired too
- Used in conjunction with an access database e.g. RADIUS
#### EAP
- Extensible Authentication Protocol (EAP)
	- An auth framework
- Many different ways to auth based on RFC standards
- EAP integrates with 802.1X to provide auth connection to net
- See vid for example

## Application Security
#### Secure Coding Concepts
- A balance between time and quality
- The QA process tests the security
- Vulnerabilities will eventually be found by an attacker / researcher
#### Input validation
- Validate actual input vs. expected
- Document all input methods
- Check and correct all input (**normalization)**
	- Zip code should only have 5 chars, etc.
- The **fuzzers** will put random types of data into input fields to exploit it
#### Secure cookies
- Cookies are used by browsers for tracking, session management, personalization
	- Not usually a security risk and are not an executable
- Secure cookies have a secure attribute set (only send over HTTPS)
- Sensitive info shouldn't be saved in a cookie
#### Static Code Analyzers
- Static Application Security Testing (SAST)
- Many security vulnerabilities found easily by it
- Not everything can be identified through analysis
	- SY0-801 will probably have this with AI analyzers...
- Still have to verify each finding
#### Code Signing
- An app is deployed
- Users run app executable or scripts
- Has the app been modified? Can you confirm it was written by a specific dev?
- The app code can be digitally signed by the developer
	- Asymm encryption
	- A trusted CA signs the dev's public key
	- Dev signs w/ private key
#### Sandboxing
- Apps cannot access unrelated resources
- Commonly used during development
	- Can be a useful prod technique
	- e.g. Staging
- Used in many different deployments
	- VMs
	- Mobile devices
	- Browser iframes
	- Windows User Account Control (UAC)
#### Application Security Monitoring
- Real time info from app usage
- View blocked attacks like SQL injected or patched vulnerabilites
- Audit the logs to find unknown vulnerabilities or hidden attacks
- Anomaly detection
	- Unusual file transfers, etc.
