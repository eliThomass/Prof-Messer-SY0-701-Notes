#### Segmenting the network
- Physical, logical, virtual segmentation
	- Devices, VLANs, virtual networks
- Can be for performance
	- High-bandwidth apps
- Security
	- Users shouldn't be taking directly to DB servers
	- The only apps in the core are SQL and SSH
- Compliance
	- Mandated segmentation
	- Makes change control easier
#### Access control lists (ACLs)
- Allow or disallow traffic
	- Grouping of categories
		- Source IP, Dest IP, port number, time of day, app, etc.
- Restrict access to network devices
	- Limit by IP address or other ID
	- Prevent regular user / non admin access
- Be careful when configuring these!
- EXAMPLE:
	- Bob can read files
	- Fred an access the network
	- James can access 192.168.1..0/24 using tcp ports 80, 443, and 8088
- Many operating systems use ACLs to provide access to files
#### Application allow list / deny list
- Any app can be dangerous
- Security policy can control app execution
- **Allow list***
	- Nothing runs unless it's approved
	- Very restrictive
- **Deny list**
	- Nothing on the list can be executed
	- Anti-virus, anti-malware, more flexible
- EXAMPLES
	- Application hash
		- Only allows apps with this unique identifier
	- Certificate
		- Allows digitally signed apps from certain publishers
	- Path
		- Only run apps in these folders
	- Network zone
		- The apps can only run from this zone

## Mitigation Techniques
#### Patching
- Incredibly important
- Monthly updates
- Third-party updates
	- App devs, device drivers
- Auto-update
	- Not always the best option, like in large organizations to account for testing of patches
- Emergency out-of-band updates
#### Encryption
- Prevent access to application data files
	- File system encryption
	- Windows EFS
- Full disk encryption (FDE)
	- Encrypt everything on the drive
	- BitLocker, FileVault, etc.
- Application data encryption
	- Managed by the app, stored data is protected
#### Monitoring
- Aggregate info from devices
	- Built-in sensors, separate devices
- Sensors
	- IPS', firewall logs, auth logs, web server access logs, db logs, email logs
- Collectors
	- SIEM (security info and event manager) is a common console
		- These often include a correlation engine to compare diverse sensor data
#### Least Privilege
- Rights and perms should be set to the bare minimum
	- You only get exactly what's needed to complete objective
- All user accounts must be limited
	- Apps should run with minimal privileges
- Don't allow users to run with admin privileges
#### Config enforcement
- Perform a **posture assessment**
	- Each time a device connects/logs in
- Extensive check
	- OS patch version
	- EDR (Endpoint Detection and Response) version
	- Status of firewall and EDR
	- Certificate status
- Systems out of compliance are quarantined
	- Set to a private VLAN until changes made
#### Decommissioning
- Should be a formal policy
- Don't just throw data into trash for someone to find
- Usually associated with storage drives
- Recycle it or destroy it

## Hardening Techniques
#### System hardening
- Many and varied
- Updates to OS, service/security packs and patches
- User accounts should have a password policy
	- Account limitations (least priviledge)
- Network access and security should be limited too
- Monitor and secure (anti-virus, etc)
#### Encryption
- Prevent access to app data files
	- Windows EFS, etc.
- Full disk encryption (FDE)
	- Encrypt everything on drive, Windows BitLocker
- Encrypt all network communication
	- Using Virtual Private Networking (VPN)
	- App encryption (HTTPS)
#### The endpoint
- The user's access to the apps and data
- Stop the attackers both inbound and outbound
- Many diff platforms
- Protection is multi-faceted
	- Defense in depth
#### Endpoint detection and response (EDR)
- A diff method to threat protection
- Detect a threat
	- Signatures can be used for this or..
	- Behavioral analysis, machine learning, process monitoring
	- Lightweight agent on the endpoint
- Investigate the threat
	- Root cause analysis
- Respond to the threat
	- Isolate the system, quarantine the threat, rollback to prev config
- This whole thing is API driven, no user / technician required
#### Host-based firewall
- Software based firewall
- Allow or disallow incoming/outgoing app traffic
- ID and block unknown processes
#### Finding intrusions
- **Host based IPS** (HIPS)
	- Recognize and block known attacks
	- Secure OS and app configs, validate incoming service requests
- HIPS identification
	- Signatures, heuristics, behavioral
	- Buffer overflows, registry updates, writing files to Windows folder
	- Access to non-encrypted data
#### Open ports and services
- Every open port is a possible entry point
- Close everything except required ports
- Control access with a firewall
- Use Nmap to verify
#### Default password changes
- Every network device has a management interface
- Change these default settings..
- Add extra security like 2FA
#### Removal of unnecessary software
- All software contains bugs
	- Some of those bugs are vulnerabilities
- Can be hard to manage ongoing updates for all
- Remove all unused software
