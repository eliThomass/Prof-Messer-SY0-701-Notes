#### Finding malware
- Malware runs in memory, therefore memory forensics can find malicious code there
- Malware contains running processes
	- Can run its own process or inject itself into a legit process

#### Memory injection
- Add code into memory of an existing process
- Get access to data in that process along with hiding in the process
	- Perform a privilege escalation

#### DLL Injection
- Dynamic-Link Library
	- Windows library containing code & data that many apps can use
- Attackers inject a path to a malicious DLL, runs as part of target process. Very popular and relatively easy to implement

## Buffer Overflows
- Overwriting a buffer of memory, spills over into other memory areas
- Developers need to perform bounds checking
	- Attackers spend time looking for openings
- Not a simple exploit, can cause crashes, takes time to make it work perfectly
- What's very useful is an overflow that is always repeatable

## Cross-site Scripting (XSS)
- Originally called cross-site because of browser security flaws
	- Info from one site could be shared with another
	- Commonly uses JavaScript
- Example
	- 1. Attacker sends link containing a malicious script to victim
	- 2. Victim clicks link and visits legitimate site
	- 3. Legit site loads in victim's browser, but the link has extra code behind the scenes
	- 4. Malicious script sends this data to hacker
#### Non-persistent (reflected) XSS attack
- Web site allows scripts to run in user input
- Attacker emails a link that that uses this vulnerability
	- Script embedded in URL executes in victim's browser
	- ***Reflects code back to hacker in a single response***
- Attacker uses creds/session IDs/ cookies to steal victim's info w/o their knowledge
- See video (number 32) for example @ 3:20
#### Persistent (stored) XSS attack
- Attacker posts a message to social network, injects the malicious payload
- "Persistent": ***everyone gets the payload once they load the page***, it stays on the network for whoever loads the page, no specific target
- Reposts can amplify the effect
#### Protecting against XSS
- Be careful when clicking untrusted links
- Consider disabling JavaScript w/ extension
- Keep browser/apps updated
- Validate input on website if you are a dev

## Hardware Vulnerabilities
- The devices that surround us are security risks & entry points
- Trust nothing, not even your stove, or anything IoT
#### Firmware
- The operating system inside the hardware
- Vendors are the only ones who can fix their hardware
	- They know the software, the OS, and the device
#### End-of-life (EOL)
- Manufacturer stops selling a product
- May continue supporting the product, but will eventually run out
- Important for security patches / updates
- **End of service life (EOSL)**
	- Support is no longer available for the product
	- No going security patches or updates
- EOSL is the more important date, EOL is a good reminder to upgrade
#### Legacy Platforms
- Some devices remain installed for a long time
- **Legacy Devices**
	- Older operating systems, apps, middleware
- May be running EOL software
	- Risk should be compared to return
- May require additional security protections
	- Additional firewall rules
	- IPS signatures for older OS'

## Virtualization Vulnerabilities
- Quite diff than non-virtual machines!
- Quantity of resources vary between VMs
	- CPU, memory, storage
-   Virtualization vulnerabilities include...
	- Local privilege escalation
	- Command injection
	- info disclosure
#### VM escape protection
- The virtual machine is self-contained... or is it?
- **Virtual machine escape**
	- Break out of the VM and interact w/ host OS or hardware
	- Once you escape, you have great control.
		- Control host & control other guest VMs
- Full control of the virtual world
#### Resource reuse
- The **hypervisor** manages the relationship between physical and virtual resources
	- available RAM, storage space, CPU availability
- These resources can be reused between VMs
	- Hypervisor host has 4GB ram, has three VMs with 2GB each of RAM
	- RAM allocated & shared between VMs
- Data can *inadvertently* be shared between VMs
	- Security risk, there is time to update the memory management features

## Misconfiguration Vulnerabilities
#### Open permissions
- Leave all the info in an open area of the internet
- Increasingly common with cloud storage
- Verizon 2017 - 14 million records exposed through Amazon S3 data repo
#### Unsecured admin accounts
- The Linux root account, windows admin account, superuser
- Can be a misconfiguration
	- Intentionally configuring an easy to hack password
- Disable direct login to the root account
	- Use the su or sudo option
- Protect accounts with root/admin access
#### Insecure protocols
- Some protocols aren't encrypted
	- Telnet, FTP, SMTP, IMAP
- Verify with a packet capture
- Use encrypted versions: SSH, SFTP, IMAPS
#### Default settings
- Every app and network device has a default login
- Mirai botnet takes advantage of default configs for IoT devices
	- Released as open-source software
#### Open ports and services
- Services will open ports, we need to manage access
- Often managed w/ a firewall to allow/disallow to specific port on specific IP
- Firewall rulesets can be complex
	- Easy to make a mistake
- Always have audits to check!

## Mobile Device Vulnerabilities
#### Mobile device security
- Challenging to secure
- Relatively small
- Almost always in motion
- Packed w/ sensitive data
- Constantly connected to the internet
#### Jailbreaking/rooting
- Mobile devices are purpose-built systems, you don't usually have acess to the OS
- Gain access by rooting (Android) or iOS (jailbreaking)
- Install custom firmware to replace the existing OS
- Uncontrolled access
	- Circumvent security features
	- The **Mobile Device Manager (MDM)** becomes useless
#### Sideloading
- Malicious apps can be a significant security concern
	- One trojan horse can make data breach
- Manage installation sources
- ***Sideloading***: Apps can be installed manually without using an app store
	- Again, MDM becomes relatively useless

## Zero-Day Vulnerabilities
#### Vulnerabilities
- Many apps have vulnerabilities we just haven't found yet
- Someone is working hard to find the next big one to either report it or exploit it for personal gain
#### Zero-day attacks
- Attackers search for unknown vulnerabilities
- Vendor has no idea vulnerability exists
- ***Zero-day attacks***
	- An attack without a patch or method of mitigation
	- A race to exploit the vulnerability or create a patch
