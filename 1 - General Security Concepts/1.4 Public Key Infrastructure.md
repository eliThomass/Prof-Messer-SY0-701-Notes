Policies, procedures, hardware, & software that is responsible for creating, distributing, and performing other processes associated with digital certificates.
- All about trust

#### Symmetric Encryption
- A single, shared key
	- Encrypt with key, decrypt with same key
	- If key leaked, you'll need a new one
- Doesn't scale very well as it's hard to distribute this key
- Very fast to use, less overhead compared to asymmetric
	- Often combined w/ asymmetric

#### Asymmetric Encryption
- Public key cryptography
- Two mathematically related keys made at same time
- Private key & public key
	- Private key is the only key that can decrypt the data encrypted with the public key
	- *Example: Encrypt message to Bob using his public key. He decrypts using his private key.*
- Math makes it impossible to get private key from public key
	- Lots of randomization and large prime numbers

#### Key escrow
- Someone else holds your decryption keys
- Your private keys are held by a 3rd party
	- ... or you can do this yourself within your organization
- Controversial, but sometimes required for availability of organization data.

## Encrypting Data
We need to protect data on storage devices
- Full disk and partition encryption
	- Bitlocker, FileVault, etc.
- File encryption
	- EFS (Encrypting File System for Windows)

## Database encryption
- **Transparent encryption**
	- Encrypt all database info with a symmetric key
- Column-level encryption (record-level encryption)
	- Encrypt individual columns, each column has own symmetric key

## Transport encryption
- Protect data traversing the network (HTTPS)
- VPN encrypts all data transmitted over the network
	- Client-based using SSL/TLS
	- Site-to-site VPN using IPsec

#### Encryption Algorithms
- Both sides decide on the algorithm before encrypting data
- Each algo has advantages / disadvantages
- The exact process is known to everyone, makes it more secure & trustworthy.
	- Only unknown is the key

#### Key Lengths
- Larger keys tend to be more secure
- Symmetric encryption uses 128-bit or larger keys
- Asymmetric encryption uses complex math with large prime numbers
	- Common to see key lengths of 3072 bits or more
#### Key stretching
- Perform encryption process multiple times on data. For example, hash the hash of the hash of a password.

## Key Exchange
How to share key across insecure medium w/o physically transferring it?

- **Out of band key exchange**. e.g. Telephone, courier, in person
- **In band key exchange**. Use asymmetric encryption to encrypt a symmetric key.
	- Symmetric session key using asymmetric encryption. Change this session key often.

#### Public Key Cryptography
- Bob combines his private key with Alice's public key.
- Alice combines her private key with Bob's public key.
	- This makes the same symmetric key for both sides without ever sending anything.

## Obfuscation
The process of making **something unclear**, but not *impossible* to understand
- Hide info in plain sight
- e.g. hide info in a image

#### Steganography
- Security through obscurity
- The covertext is the document that contains the data you are hiding
	- Can hide through many means, such as embedding messages in TCP packets
	- Embed message in image
	- Invisible watermarks

#### Other steganography types
- Audio
- Video 

#### Tokenization
- Replace sensitive data with a non-sensitive token
	- SSN 266-12-112 is now 691-61-8539
	- Transfer modified number across network, then we can make the switch to real number
- Common with credit card processing
	- Use a one-time token from credit card number
- NOT encryption or hashing

#### Data Masking
- Data obfuscation
	- Hide some of original data
	- e.g. Bank card: \**** \**** \**** 2512 on receipt
-  Protects PII
- May only be hidden from view
	- Control this view based on permissions
- Many diff techniques, like substituting, shuffling, encrypting, masking out, etc.

## Hashing and Digital Signatures

#### Hashes
- Represent data a short string of text
- One-way, cannot recreate message from hash
- Used to verify a downloaded document is the same as original
- Can also be used for a digital signature
	- Auth, non-repudiation, integrity

An example: SHA256 - 256 bits, 64 hexadecimal chars
- My name is Eli Thomas
	- SHA265: eca67442a527d7e98ecd3472aaa198d145ce7f1d0110db1069252aa0100cd341

#### Collisions
- Hash functions take in any size input, output a fixed size string
- Hash should *ALWAYS* be unique
	- If different inputs create the same hash, that's a **collision**
		- These should be extremely rare

#### Practical Hashing
- *Verify a downloaded file* by comparing downloaded file hash with posted hash value online
- *Password storage* instead of storing a plaintext password, store a hash w/ salt
	- Compare hashes during auth process
	- Company never holds your actual password, nor an encrypted version

#### Salt
- Random data added to a password when hashing
- Every user gets their own random salt
	- Often used with passwords so same password still makes diff hashes
- Rainbow tables don't work with salted hashes since random value added
- Also slows down brute force process

#### Digital Signatures
- Prove the message was not changed.
	- Integrity
- Prove the source of the message
	- Authentication
- Make sure the signature isn't fake
	- Non-repudiation
- Sign document with sender's private key
	- Verify with the sender's public key
- Any change in the message will invalidate the signature

## Blockchain Technology
- A distributed ledger, job is to keep track of individual transactions
- Everyone on the blockchain network maintains the ledger
	- Records & replicates to everyone
- Many practical applications
	- Payment processing
	- Digital ID
	- Supply chain monitoring
	- Digital voting

#### The blockchain process
- A transaction is requested
- Transcatinos is sent to every computer
- Verified transactino is added to a new block of data containing other recently verified transactions
- A hash is added to the new block of verified transactions block and is calculated from the previous blocks of transaction data in the Blockchain.
-  Block if added to the end of the Blockchain and all nodes updated
- If any blocks are altered, it's hash and all following hashes are automatically recalculated.
	- The altered chain will no longer match the chains stored by the rest of the network, and will be rejected

## Certificates
- A public key certificate
	- Binds a public key w/ a digital signature
- A digital signature adds trust
	- Combine with a certificate authority for extra trust
	- **Web of Trust** (multiple individuals sign each others certs)
- Certification creation can be built into OS, like if the data isn't leaving your organization

#### What's in a digital certificate?
- X.509 is standard format
- Cert details
	- Serial number
	- Version
	- Signature Algo
	- Issuer
	- Name of cert holder
	- Public key
	- Extensions

#### Root of trust
- How to build trust from something unknown?
- Have a 3rd party vouch for the thing you are connecting to (e.g Root of Trust)
- Root of trust
	- An inherently trusted component
	- Hardware, software, firmware, etc.
	- Hardware security module (HSM), secure enclave, cert authority, etc.

#### Certificate Authorities
- Need good way to trust unknown entity
	- Use a trusted 3rd party called a **Certificate Authority.**
- **Certificate Authority (CA)** has digitally signed the website certificate
	- You trust CA, therefore you can trust the site
- Built into the browser, there will be hundreds of CA 
	- Purchase your web site cert
	- CA is responsible for vetting the request to confirm certificate owner

### Certificate signing requests
- Create a key pair, then send the public key to the CA to be signed.
- The CA validates the request
	- *Confirms DNS emails and website ownership*
- CA digitally signs the cert and returns

#### Private certificate authorities
- You are your own CA
- Your devices must trust the internal CA
- Needed for medium-to-large organizations
	- OpenCA, Windows Certificate Services

#### Self-signed certificates
- Internal certs don't need to be signed by a public CA
- Build your own CA
	- Issue your own certs signed by your own CA
	- Same exact process
- Install the CA certificate chain on *all devices*

#### Wildcard certificates
- aka **Subject Alternative Name (SAN)**
	- Extension to a X.509 Cert
- Allows a cert to support many different domains
	- e.g.  \*.birdfeeder.live
- Wildcard domain
	- Useful for applying to all server names in a org's domains
#### Key revocation
- **Certificate Revocation List (CRL)**
	- Maintained by CA
	- Can contain many revocations in a large file
- See heartbleed online
- Your browser connects to a 3rd party website -> website provides browser with it's cert -> browser looks thru cert to find CRL URI to download CRL list. Make sure this cert isn't in the revoked list.

#### OCSP stapling
- Online Certificate Status Protocol
	- Provides *scalability for OCSP checks*
- Have the cert holder verify their own status.
	- Status info is stored on the cert holder's server
- OCSP status is "stapled" into the SSL/TLS handshake
	- Digitally signed by the CA
- Better than downloading an entire URL list
